## 3. 数据库与账号迁移

联合数据库版本为 **26**，分别识别官方22/23、本地23/24/25的实际列，补齐auth_mode、窗口类型/输入上限、B、发送策略和失败表。不引入destructive fallback，未知升级/降级路径失败保数据。

OAuth最终profile重写纳入实际JSON计量。旧codex_subscription规范化为新认证模式，真实请求工厂不再调用旧刷新owner；遗留适配器仍有离线兼容测试，不能重新挂回生产路径。

登录、退出、忘记账户使该Provider发送策略失效；普通token刷新不失效。由于失败记录key是私有HMAC、不含Provider列，身份更改时保守清理内容无关失败元数据；不清历史或断点。Room更新通知已接线。旧凭据导入失败记录固定阶段和异常类型，不记录正文/token，不删除旧文件。

### 安装中补修的实际问题

首候选2203安装核对发现上游预设升级把3个自动窗口值写进手工override。已：

1. 修正预设初始化和fill窗口路径，让自动值继续保存在自动字段；模型编辑框保持“显示自动值、未编辑不制造override”。
2. 保留退休预设中已有的用户窗口/推理/请求覆盖，不因目录升级删除这些配置。
3. 在手机私有目录再次备份中间DB26，只对匹配原DB25备份且符合误写条件的3条记录恢复null override，核验changes=3及quick_check=ok。
4. 编译同证书2301并再次备份覆盖；最终原模型容量/手工覆盖和请求配置与2202备份对比为0变化。

上游目录正常清理了5个旧OpenAI内置预设；这些条目没有会话引用，也没有窗口/推理/header/body用户覆盖。新增Grok的1个提供商及1个模型，最终模型数 **88→84**、提供商 **13→14**。不能将其描述为“所有数据库行数原样不变”；用户历史、仍存在模型的启用/显示/手工配置、原Provider凭据/地址/预算均经核对保留。

## 6. 用户需要注意和后续验收

1. **不要直接用旧DB25包或官方DB23包降级覆盖**；回退需应用和私有数据库/状态配套恢复，备份不能直接当成新版运行库复制。
2. 新版输入交互：发送短按排队；运行中长按发送可中断后另起一轮；“本轮补充”保持当前run，不取消当前工具。三者不是同一动作。
3. v4仍关闭，原模式继续使用；本次没有替用户开启新压缩引擎或提高发送边界。
4. 仍需用户/另行授权实机验收：小布冷/热ASR、停顿/完成/闲置恢复；真实订阅登录/刷新；运行中补充与队列；长会话切API、压缩质量/时延/取消续压；GUI操作时旋转不变。没有新的真实模型请求，不能以离线测试声称这些已完成。
5. Windows未覆盖的POSIX终端、descriptor unlink、原图预览场景需Android/Linux条件复核；当前终端Linux rootfs仍可执行手机私有SQLite验证，但不等于所有终端交互已验收。
