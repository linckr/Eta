## 0. 先核对事实

- 已读本地封存 `.analysis/review-20261021-live/live-check-summary.txt` 及对应 log：纯字节触发的摘要累计 80,766 ms 后 `CONTEXT_SUMMARY_INVALID`；回退聊天 HTTP 约 1.6 秒结束。不能宣称 2002 已修好首次或跨用户轮的摘要失败。
- 同一次 20,300 字符响应，Trace `4ddcded2-203f-4a43-8261-5aad3d3fba27` 的 `read_completed` / `http_call_completed` 为 usage_events=0，`provider_completed` 为 1；最终聊天 Trace `f0d32b0d-ca60-4893-9e53-7c7f97eb46c0` 的 provider_completed 也为 1。

## 1. usage 是可选观测，不是业务前提

### 1.1 统一状态

每次尝试在应用层最终事件保存以下允许列表，不从中间 HTTP 事件推断账单：

| 字段 | 值与意义 |
|---|---|
| usage_status | valid_input / partial / missing / malformed |
| usage_source | terminal_response / stream_event / documented_header / none |
| input_tokens、output_tokens、cached_tokens、reasoning_tokens | 有合法数值才写，否则 NULL；缺失不写 0 |
| estimator_kind | provider_count / verified_local_tokenizer / calibrated_heuristic / uncalibrated_heuristic |
| estimator_version、calibration_sample_count | 对应当前模型、端点、协议投影及算法版本 |

valid_input 要求明确的、非负整数 input_tokens（非空请求的 0 视为异常）；检查缓存输入不大于总输入等已知一致性条件。只有输出或 total_tokens、没有可靠分解时是 partial，不能把 total_tokens 当输入直接校准。

HTTP 失败/缺少终态不把中间 usage 自动当最终计费凭据。日志增加 usage_parse_status 和固定路径标识，不保存原 usage JSON、响应头任意值或正文。

### 1.2 三种估算模式

1. 有已验证本地 tokenizer，且文本/工具模板与模型匹配：用它估算；图片、原生不透明状态仍需单独标记未知部分，不声称整份输入精确。
2. 有有效 input usage：仅用同一路由/模型/投影的可比较样本校准；缓存 token 不从容量占用中扣除。至少 20 个有效样本后才标为 calibrated；另留独立样本检验，不能训练和验收用同一份数据。
3. 没有有效 usage、也无可信 tokenizer：继续使用现有估算，但首轮候选使用 `E_guard = ceil(1.25 × E_base) + 4096` 做保守规划，统一以 E_guard 比较 85%/60%。明确显示“未校准估算”。这不是数学上界，不能拿它证明请求一定不超窗。

若后续观测证明低估，立即退回未校准模式并失效旧校准。未知窗口时保持“未知”，不通过公式推导一个真实窗口；同时执行第 2 节本地发送边界。真实容量拒绝进入受限恢复，不无限试探。

### 1.3 验收

- 覆盖：usage 正常、只给输出、只有 total、缺失、乱类型、负数、重复终态、流中断、缓存缺失等，状态和 NULL 处理 100% 正确。
- 有真值的模式使用至少 1,000 条独立离线文本/代码/JSON/中文/工具输入样本；保守估算覆盖率 >=99.5%，最大低估比例 <=5%，分别报告各内容类型。这个门槛是工程准入，非模型容量保证。
- 没有真值的模型只能通过“估算降级与恢复行为”验收，不能标注 tokenizer/校准准确率通过。账单与缓存验收另见第 4 节。

## 2. B/L/H 唯一映射与发送顺序

以 [v3 第 1–2 节](CONTEXT_COMPACTION_POLICY_MIGRATION_V3_2026-10-22.md) 为唯一可执行条款：

| 旧 request_byte_budget | 新 B | 新 L |
|---|---|---|
| NULL | NULL：无额外软字节触发 | 独立路由策略值 |
| 正数 X | X：严格 S>X 时软触发 | 独立路由策略值；不自动等于 X 或 max(X,L) |
| 0 | 0：关闭软字节触发 | 独立路由策略值 |

先检查 token、B、L、H 是否需要整理；B<S<=L 不能直接绕过 B。软优化结束/延期后仍须做 L/H 检查；原请求仍越 L 不自动回退上传。B>L 保留值但提示护栏先触发。

本次 DeepSeek 精确候选边界为 1,782,914 B（约 1.783 MB/1.700 MiB），不向上取整；2 MiB 只在专门验收或用户明确配置后启用。该数不是 API 容量证明。其他路由与许可记录的五分钟/单次 HTTP/载荷绑定规则见 v3，不从其他 Provider 继承。

## 3. 必须先解决摘要失败本身

不能用关闭字节触发来通过摘要功能验收。默认迁移的前置门槛是：同一来源在真正 token 压力下，摘要能形成完整可用的新窗口。

### 3.1 完成状态、输出目标、内存上限分开

- 模型输出目标候选：最多约 8,192 tokens，参数只在能力确认支持时发送；token 估算不确定时如实标记。
- 新便携文本引擎的原始正文捕获内存上限候选为 256 KiB UTF-8，独立于 12,000 字符历史规则。达到捕获上限时按明确的响应容量错误结束；不裁切后冒充完整摘要，不写覆盖游标。
- 完整 END_TURN、非空、没有实际工具调用、没有实际协议泄漏，是必要条件；这些本身不能证明事实质量。
- 完整文本即便为 20,300 字符，只要完整最终请求符合有效容量、目标与质量约束，就不因超过 12,000 字符失败。若只满足容量、不满足软目标，走“余量有限”判定，不等同于结构无效。
- 最终候选仍过大时，只允许一次指定实际长度/目标和事实保留要求的精简；该精简占用本轮共享恢复额度，不另开一套重试。
- 实际截断、无 END_TURN、空响应或实际泄漏，不能通过放宽字符数放行。旧结构化 JSON 也不能因切到文本模式就把无效补丁当作摘要；需要明确的引擎切换和来源验证。
- 新增固定诊断：engine、stage、rejection_reason、response_chars、response_utf8_bytes、limit_kind、limit_value、candidate_bytes、input_usage_status、completed。区分 text_soft_target / capture_memory_cap / legacy_text_limit / json_schema / token_capacity；没有数据就记 NULL。

### 3.2 延迟与恢复预算

不先把 45 秒作为默认。按 v3 第 3 节比较 45/60/90 秒候选，选择满足自动完成率>=95%、预算暂停率<=5%、需手动介入占比<=5%及质量/费用门槛的最短预算；不满足则修引擎并维持旧策略，不能仅缩短失败等待就上线。

整次预算包含全部片段/共享恢复，现有单次 120 秒上限不扩大。暂停必须保留草稿、原请求、附件引用、Journal 和已验证断点；手动续压不计作自动成功。完整分母、试点/正式样本、取消与 fallback 的计数见 v3。

### 3.3 必过用例

| 输入/响应夹具 | 必须达到的结果 |
|---|---|
| 完整 12,343/13,202/20,300 字符文本，最终候选容量合格 | 不报旧的 12,000 字符错误；候选来源、质量和提交条件独立检查 |
| 20,300 字符，但候选超过 token/L 目标 | 最多一次精简，合格才提交；不把仍超限结果写入活动窗口 |
| 不完整 8,000 字符、未结束 JSON、工具协议泄漏 | 不提交，恢复总额度仍为一次 |
| 最终捕获超过 256 KiB | 明确响应容量错误，历史/断点不变，不本地裁切 |
| 80,766 ms 的旧失败时序回放 | 自动流程在候选预算内结束/暂停且后续补充不重开同源失败；只证明失败上界，不通过自动成功率验收 |
| 真正达到 85% 的同源历史 | 能在质量合格的摘要后继续；此用例失败则不能以“1.78 MiB 直接聊天正常”替代通过 |

第一组是新文本引擎的结构夹具；事实质量另有基准。原 20,300 字符真实响应若没有授权保存正文，只能用等长夹具验证边界，不声称重放了同一语义输出。

## 4. 可执行验收数字

这些数字是产品发布门槛，**不是现在已经通过的结果**。不满足就调整参数或保留试用，不能把数字降到适配一次成功。

### 4.1 样本与分组

- 离线至少 12 份固定历史，覆盖工具密集、中文/代码、旧失败/新状态、超长单工具结果、旧断点、图片与签名状态；投影到 128k、256k、1M 三种输入预算，共至少 36 个场景组。
- 不同协议、Provider、窗口分别报结果，不把一条历史的 200 轮当成 200 个独立场景。
- 质量评测至少 3 份有人工/原文核对答案的固定历史，各至少 50 项相关事实，其中至少 15 项关键约束/操作结果；标注在看候选摘要前冻结。
- 真实模型验收按路由先做至少 5 对基线/候选场景，用相同提示、后端、思考/输出参数和后续工作负载配对；能用已有冻结基线就不重复消耗。最终路由级 P95 需要至少 20 次有效压缩观测，样本不足仅报原始值和中位数。
- 请求条数/费用上限在每批真实验收前单独审批，超过停止并标记样本不足。本文件不授权新请求、手机操作或工具执行。

### 4.2 压后多少轮不再触发

“轮”指一次模型请求（含工具后的请求），不是一条用户消息。

- 固定协议、工具目录和受保护部分，成功达到 token <=60%I、字节 <=75%L 后，接续 10 轮；每轮新增分别不超过 2%I 和 2%L，且无其他容量/配置变化：**重复自动压缩次数必须为 0**。
- 此条件测试固定估算器及版本，逐轮测量最终投影差值；无真实 token 真值的路由只能称“估算范围内通过”，不能宣称实际容量证明。线上因校准修正或模型变化触发的请求单独分类。
- 因为 10 轮最多增长 20%，仍低于 85% token 触发和 L；每次候选都须用完整最终协议复测。没有达到目标的样本不混入本组。
- 实际大工具结果一次可越过余量，不承诺固定 10 轮；另报“距再次触发所增加的 tokens/bytes”和原因。
- 对未达目标、无收益、结构失败，连续 10 次同源用户补充/工具轮：不得自动重复同一持久性失败；手动重试和版本失效另测。

### 4.3 信息保留

- 关键用户约束、禁止事项、已确认完成操作/关键结果：**100% 保留，错误陈述 0**。
- 全部标注的“后续仍相关事实”保留率 >=95%；已失效尝试不作为必须保留项，但新旧状态关系不能颠倒。
- 未获证据支持的新增关键事实为 0；不以同一被测模型的自评单独计分，采用冻结答案及人工/确定性核对。
- 原文回查至少 20 个预先选定问题：结果、来源区间和关键数值一致率 100%；这是 Journal 检索质量，不算摘要正文保留率。
- 安全边界、覆盖终点、取消、编辑、落盘失败及无工具重放：所有夹具 100% 通过。
- 语义保留率是发布评测，不是客户端每次自动证明。运行时检查来源/覆盖/完整响应/预算，不默认另发一轮模型评审来增加费用，也不能将这些工程校验等同于理解了全部事实。

### 4.4 延迟、成本、缓存

- 自动预算按 v3 的 45/60/90 秒成对测试与成功/暂停/手动介入门槛选定，不预先默认 45 秒；成功样本中位数目标 <=20 秒，失败/取消也计入端到端延迟分布。手动续压必须计入介入率，不能冒充自动达标。
- 原 80 秒同源自动失败不得在后续每条补充重现；无压缩发送的本地准备 P95 <=2 秒（受控设备/数据规模下），网络耗时单列。
- 同一压后接续 20 轮工作负载、包含摘要请求本身：有真实计费数据时，总费用不得超过基线 110%，且压后前 10 轮累计输入 token 至少下降 20%。质量必须先过关，不能靠漏发历史降成本。
- 缓存命中率计算为 `Σcached_input / Σinput`，按窗口重建后的第 1 轮与第 2–20 轮分开；首轮缓存损失预期但要计入总费用。可比较的第 2–20 轮命中率较基线下降不得超过 10 个百分点，否则不通过性能验收。
- 没有缓存数值或价格/计费数值时标 N/A，不能当 0，更不能宣称成本/缓存验收通过。可用供应商可关联账单作为真值；否则只报告估算费用/本地输入量，性能发布门槛保持未验收。有限试用与正式默认发布分开决定。
- 基线必须是同样能完成任务的可比较策略；旧策略已经失败时，先报候选绝对调用量/成本与完成率，不能用一个失败基线凑费用优势。

### 4.5 新增量门槛：取消统一 10%I

10%I 对 128k 约为 12.8k，对 1M 约为 100k，不能作为格式错误的自动恢复条件。

- **持久性格式/正文容量错误：新增量不解锁。**版本、配置修正或用户手动重试才解锁。
- 对已确认无收益的摘要，候选新增量门槛为 `clamp(2%I, 4096, 16384)`，未知 I 用 8192；分别得到 128k→4096、1M→16384。
- 若只存在字节压力，也可在新增可压缩原文达到 `clamp(B/4, 64 KiB, 256 KiB)` 时重新评估；不是仅凭一条新消息的时间戳解锁。两种新增量条件任一达到可评估一次，仍受一次任务内重复抑制与 L/H。
- 夹具在门槛-1/门槛/门槛+1 检查；达到只允许一次重新评估，失败重新记录基线；不得在随后 10 个低增量请求中再次尝试。
- 这个门槛只控制可选字节优化的价值判断，不允许跳过 token、已知 H、L 的发送检查。

## 5. 跨运行记录：Room 设计

### 5.2 来源摘要与性能

全文前缀 HMAC 的执行方案已被 v3 第 5 节取代。canonical_version=2 使用流式消息叶摘要、持久化有序范围树和对范围根的 HMAC；尾部追加与内容编辑增量更新，插入/删除/重排分批失效重建。

scratch<=2 MiB、每块<=64 KiB、单后台工作者；热区间查询 P95<=20ms 的候选门槛，以及 5,000/10,000 条/16–128 MiB 的冷热索引验收按 v3。不能为哈希重新编码整个消息列表。旧失败记录版本失效，但旧摘要/270 段断点不删除。

### 5.3 失效与并发

| 事件 | 处理 |
|---|---|
| 同源追加少量用户文本/工具结果 | 记录仍有效；按失败类别判断，不清除 |
| 源范围编辑/删除/重排、活动摘要改变 | digest/generation 不匹配，失效旧记录与旧候选，重新检查依赖 |
| 换摘要后端、模型、端点或账号 | 新 route/engine 记录作用域，不盲套旧失败 |
| algorithm/prompt/budget/estimator/canonical 任一版本变化 | 旧失败不阻止新算法尝试；已验证成果是否兼容另行检查，不能删除旧断点 |
| 成功提交摘要 | 同一事务递增 generation、更新快照并删除/终结相应失败记录 |
| 应用重启 | 读取记录；过期 lease 释放，失败原因仍保留，不伪造运行中 |

提交候选必须在事务内验证源前缀、摘要 digest 和 generation。新增尾部可保留拼接，前缀冲突拒绝旧提交；记录更新不能使未验证摘要成为活动快照。

### 5.4 手动重试如何绕过

会话通知提供“重试压缩”入口。点击原子获取一次 `retry_nonce/lease_owner`，忽略这一条失败抑制记录一次，仍检查 token/H/L、源版本、取消、权限与共享一次恢复上限。连续点击同一 lease 不产生第二个请求。

自动任务 lease 候选 120 秒，手动任务 660 秒；若运行未结束应通过持有者验证/心跳续租而非仅按墙钟抢占。进程死亡或明确结束释放租约；成功清记录，失败更新同一记录，不立即再触发自动重试。

### 5.5 按原因处理，禁止“一把 10% 门槛”

| 类别 | 自动恢复条件 |
|---|---|
| FORMAT_PERSISTENT（同次恢复后仍格式/长度不合格） | 手动、算法/提示/参数修正；新增 tokens 不解锁 |
| NO_REDUCTION | 满足第 4.5 节新增量，或版本/预算调整；允许一次价值重评估 |
| TRANSPORT_TRANSIENT | 下一次用户操作且距失败至少 60 秒，可受限尝试一次；无后台定时请求 |
| CAPACITY | 当前窗口/发送检查必须重做；相同格式失败不被硬压力反复自动调用，不能安全发送则提示手动继续 |
| AUTH/QUOTA | 账号/配置修正或手动；不伪装为摘要内容问题，不切供应商 |
| CANCELLED/STORAGE/UNKNOWN | 不建立可放行原请求的软失败记录，继续原有停止或失败规则 |

用户手动重试与版本失效不受新增量门槛限制。token 或 L/H 压力永远不会被“暂缓摘要”变成允许超限发送；必要时暂停任务并保留全部状态。

### 5.6 隐私与迁移验收

- 记录只保存固定枚举、计数、私有哈希和稳定内部 ID；不保存聊天、思考、摘要正文、工具参数/结果、完整 URL、密钥或任意错误文本。额外错误详情沿已有允许列表。
- trace_id 只接受已验证 UUID，rejection_reason/limit_kind 只接受固定枚举；nullable 计数字段不把缺失写成 0。多个 HTTP 尝试通过已有安全事件串关联，不在失败表累积无限数组。
- 用含敏感标记的夹具验证 DB/遥测新字段不出现正文；旧 DB 升级后会话、消息、Journal、配置计数和内容校验不变。
- 必测：重启后仍抑制；旧版本升级立即允许新策略一次；两次点击只建一个运行；同源追加不失效，编辑必失效；账号变更不串记录；保存事务失败不改快照；删除会话级联；密钥丢失只失效失败记录。

## 6. 上线顺序（以 v3 的联合交付为准）

1. **观测与根因修复先行**：补齐最终有效 usage 与摘要拒绝诊断；实现文本长摘要的预算型接收/精简及共享恢复。12,343/20,300、实际 token 压力与 45 秒上界均通过，才继续。
2. **Room 状态与发送护栏**：迁移/隐私/失效/手动入口及 L/H 检查一起交付。不能先关字节触发、后补未知上传保护。
3. **增量摘要与双目标**：两条旧路径和新文本引擎使用同一候选规则，验证 10 轮、关键事实、Journal 与断点。
4. **成对真实验收与默认迁移**：达到功能、质量与可观察性能门槛再更改 null 默认；usage 缺失的路由成本/缓存仍标待验收，不能汇总成“全部通过”。

原生接口不作为以上四步的前置依赖。本次仅修订设计，不实施迁移、修改手机或调用模型。
