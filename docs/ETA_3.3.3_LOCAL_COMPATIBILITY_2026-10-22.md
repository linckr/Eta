# Eta 3.3.3 本地改造兼容性与迁移清单

审计日期：2026-10-22。统筹及三组专项审计：上游增量、非压缩本地能力、上下文与数据。

## 1. 结论

**可以以 3.3.3 为新基线迁移，但不是直接覆盖升级。** 当前仍为 3.3.1-local / 2026102202；本次完成核对和清单，没有迁移业务源码、编译或安装新版，没有发送模型请求。

最重要的三个合并关口：

1. **数据库已经分叉。** 官方 DB23 与本地 DB23 的结构不同；本地现为 DB25。需要新的联合版本和两条历史路径测试，禁止引入清库兜底。
2. **官方 Codex 认证与本地实现重合。** 采用新认证骨架时，必须承接旧账号、登录方式和安全刷新语义，不能直接删除本地凭据实现。
3. **官方排队/中断不等于本地本轮补充。** 必须保留用户可区分的操作和 ACK/去重、草稿保护，不能把取消当前 run 当作原来的补充。

本地压缩、请求预算、失败恢复及小布适配的主体仍需保留。普通运行中听写、浮窗思考预览可采用上游已有实现，避免重复维护。

### 2202压缩契约必须随迁移保留

- token压力85%触发；所有v4候选提交不超过80%有效输入预算，60%为提前目标。不能把95%候选提交后称作恢复完成。多轮不再压缩的承诺仍受后续新增量约束。
- v4 null B关闭自动字节软触发；旧模式仍可派生512KiB/1MiB。正数显式B是软触发，不能用L覆盖其意图。
- 无观测时bootstrap anchor512KiB、growth256KiB、L768KiB，受H裁小，不能继承旧48MiB B。旧bootstrap版本需明确重新启用。
- scope稳定不等于断点无条件复用；追加可复用已消费前缀，已消费历史编辑、工具批次或结构变化必须失效。跨会话不得混用。
- 最终发送护栏覆盖实际序列化后的恢复/重试请求；确定性失败抑制不能绕过token/L/H。超过发送边界且不能安全压缩时明确停止，不能悄悄发送原请求。
- 原Journal、已验证断点、取消恢复、写入失败保护和提交顺序不变。旧结构化/树/文本进度与v4并存，未实现完整CAS体系不可在报告里补称已完成。

## 4. 迁移阻断和重点整合

### 4.1 数据库联合版本

|起点|实际结构差别|
|---|---|
|官方22|尚无下述分叉字段|
|官方23|新增model_providers.auth_mode|
|本地23|新增provider_models.context_window_kind / input_token_limit；没有官方auth_mode|
|本地24|再新增model_providers.request_byte_budget|
|本地25|再新增request_send_policy_json和compaction_failures|

建议新联合DB版本至少26。对官方23与本地23查询实际表结构并补缺，分别测试旧22、本地24/25路径；不能仅靠版本数字识别。新实体、Room身份、索引/外键、历史/分块、所有provider字段须一致。

**上游包含fallbackToDestructiveMigration，本地必须继续未知路径失败保数据。不要直接安装官方3.3.3覆盖本地DB25。** 即使设备允许不同签名安装，也不能解决数据库降级和KeyStore兼容问题。

### 4.2 Provider认证、最终请求与计量

上游新增authMode/profile会改写端点和实际JSON；Grok后置重写、Codex不支持的输出字段均要纳入最终builder。计量请求必须等于实际发送请求。401刷新后是另一次物理call，须重新绑定Trace并遵守重试与可见输出保护。

路由scope需纳入认证模式、最终profile与稳定账号身份，不记录token，不因短期token刷新使所有断点失效。旧本地全局Codex凭据与新按Provider存储格式不同：只有本机解密、映射、原子写入并读回成功后，才可结束旧存储使用；不得让两套刷新owner并行争用。

### 4.3 UI加载、队列与完整历史

以官方新分页、导航恢复、队列为骨架接回本地行为。未加载正文不能持久化成空历史；模型history/Journal不能缩成UI可见页。队列切换须等待上轮取消/终态和持久化；本轮补充仍需runtime ACK，入列成功不是补充已接受。

### 4.4 新上游能力完整保留

应吸收Codex/Grok认证、Gemini/MiniMax TTS、ASR总开关、历史按需加载、LaTeX解析修复、新网页后端和常亮生命周期。Web工具新summary/分页会增大工具结果，仍应通过最终模型请求预算；Web凭据不能进入普通报告/日志。

官方与本地versionCode恰均为2026102202；迁移产物应更高。SDK合同未变，官方新增arm64-only；RMX3888适用，但原x86模拟器不能承担新原生库验收。保留本地签名连续性，构建时另核证书，不凭同名环境变量判断一致。

## 5. 外部改造边界

- **WorkBuddy网关**是独立资产，本次不更新、不重启、不读取账号配置。Eta侧须保留X-Trace-ID以及匹配回显和X-WorkBuddy-Gateway-Error=request-receive-v1的信任条件，不能凭错误文本重试；新认证不能绕过此限制。
- **EtaSteer旧外部包**基于3.0.4，缺当前ACK/去重及新队列合同。其补充语义仍有保留价值，但`EtaSteer/eta-steer.patch`及整文件替换不再可作3.3.3迁移方法。
- **手机私有技能、终端数据**是安装保留检查项，不属于官方APK已替代的源码改造；本轮没有重新读取其内容或证明其完整运行兼容。
- **MagicNet核心、lazy_start和Tailscale网络修复不属于Eta迁移清单**，本轮不改手机网络，也不把它们列为Eta3.3.3的合并前置任务。

## 6. 建议实施顺序与验收门槛

1. 固定本次HEAD与3.3.3，新隔离分支建立联合DB版本；先通过两种23及22/24/25的无损升级测试，未知schema失败保数据。
2. 合并认证/模型目录与最终请求构建；离线fake/回环验证Chat、Responses、Anthropic、Codex、Grok的序列化、401、Trace、输出字段限制及护栏。
3. 迁入2202压缩与所有旧引擎；复用已有回归并新增auth/profile切换、B=null/0/48MiB、L/H等号/超1B、追加/编辑断点、取消重开和存储失败用例。
4. 以新队列/分页为骨架接回本轮补充、原会话继续及小布ASR；验证ACK丢失、重复、在途改草稿、队列撤回附件、停止不连发、归档去重。
5. 合并语音总开关、新TTS、Web、常亮、旋转保护和资源；统一编译后核签名、版本、ABI及必要离线回归。
6. 安装前单独获准私有备份/覆盖安装。真实登录、模型、摘要质量/时延/成本、小布说话、实际旋转验证按后续授权范围开展。当前不以315次旧测试执行替代3.3.3验收。

最低放行条件：DB无损；旧能力清单无丢项；实际JSON计量一致；工具不重复执行；旧断点保留；队列与本轮补充语义明确；私密数据不进入日志/备份；真实验收边界明确记录。

## 7. 当前证据边界及附件

本轮只查源码、官方发布信息及目标手机包版本。2202既有记录为已安装、DB25保留、v4关闭、未发送真实模型请求；279项SDK36与36项SDK33是历史执行记录，不证明3.3.3合并、v4摘要质量、实际上界或真实订阅兼容。本次没有新增运行通过结论。
