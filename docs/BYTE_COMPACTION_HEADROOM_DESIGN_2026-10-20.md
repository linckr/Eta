# 压缩后的字节余量设计

日期：2026-10-20。状态：设计稿；2026-10-21 已在候选分支实现分层路径第一版（目标/保留候选/遥测），未构建、未安装、未真机验收。DeepSeek 的 2 MiB 显式覆盖验收与本设计分开进行，当前验收不证明余量机制有效。

## 1. 已确定的范围

- 1 MiB 派生默认 PR 保持 draft / 待评估，不作为所有大窗口模型的最终默认合并。
- 2 MiB 仅是 DeepSeek 单 Provider 的显式覆盖候选；不提高全局默认，也不借此声称供应商硬上限。
- 208 个请求的 shadow 样本支持继续评估，不能替代启用新策略后的真实压缩频率、信息质量和延迟验收。
- 本设计解决触发后停在阈值附近的问题，不以更早触发或额外重试替代余量。

## 2. 现状与需要调整的位置

AgentContextSession.prepareForRequest：严格 requestBytes > B 才产生字节压力；token 仍使用现有独立保护。

AgentContextSession 的 candidateFits 回调：token 估算要求不超过有效输入预算的 80%，字节要求仅为 <=B。因此一个 2 MiB 预算下的 1.99 MiB 候选也可能触发早停，新增工具结果容易再次越线。

candidateFits 主要控制有完整工具边界时的提前结束。AgentContextCompactor 和分层路径在正常处理完全部可摘要历史时还存在终态返回路径；不能只把回调从 B 改成 0.75B，就宣称所有最终结果都达标。实施时应统一评估提前候选与正常终态候选，并把未达软目标与校验失败区分。

## 3. 双阈值方案

定义 B 为当前请求实际解析出的软预算，T 为压后余量目标。

- 触发条件保持原样：字节数 >B。不得把 T 当作新的触发线。
- 仅当本轮由 byte 或 both 压力触发，且 B>0 时，启用字节余量目标。
- 第一轮离线候选：T=floor(B×3/4)，即尽量留出 25% 的预算空间。75% 是待验收的工程参数，不是已由 208 个样本证明的最优比例。
- 使用 Long 计算，避免 B×3 溢出。显式 0 表示没有字节目标；极小正预算可能产生不可满足的目标，应如实记录，不能修改用户设置来凑目标。
- 纯 token 压力、手动压缩、任务结束时的既有压缩保持原有行为，第一版不额外要求它们达到新的字节余量。

| 当前 B | 达到字节触发的条件 | 本轮候选 T |
| --- | --- | --- |
| 512 KiB | >524,288 B | 393,216 B（384 KiB） |
| 1 MiB | >1,048,576 B | 786,432 B（768 KiB） |
| 2 MiB | >2,097,152 B | 1,572,864 B（1.5 MiB） |
| 0 | 不由字节触发 | 不适用 |

例如当前请求为 1.59 MiB、预算 2 MiB 时，不因为高于 1.5 MiB 目标而压缩。只有超过 2 MiB 后，才在这一次压缩中争取压到 1.5 MiB。

## 4. 候选评估与正常结束时的有限退让

将单一的 Boolean candidateFits 扩展为内部候选评估结果，至少区分：

1. 完整性：原有结构/来源验证、完整消息与工具边界、受保护用户请求、协议状态约束。
2. 既有 token 保护及目标的结果：不得因追求字节余量而放宽现有容量保护，也不在本次设计中把 token 估算升级为新的供应商硬容量声明。
3. 实际最终协议体：用 AgentProviderRequestJson / AgentRequestBudget 计算，包含工具定义、指令、协议保留字段等，不用 UI 字符数或摘要正文长度代替。
4. 字节是否实际缩减、是否 <=B、是否 <=T，以及剩余余量 B−afterBytes。

处理顺序：

- 满足完整性、既有 token 条件且 <=T 的候选：可提前结束。
- 仅达到 <=B、尚未达到 T 的有效候选：保存为本轮可用的退让候选，继续在现有摘要流程内处理其余安全历史边界；不把它提前宣称为“余量已达标”。
- 只有正常耗尽本轮可处理历史、没有异常且完整验证通过时，才可考虑使用保留的有效退让候选；结果标为“已缩减、目标余量未达到”。不得为凑目标无限重新归并同一份已验证事实。
- 连 <=B 都未达到：B 仍是软预算，不能仅因此新增硬拒绝或强删历史。沿用现有无收益/失败/P0 与 token 保护边界，并明确记录尚有字节压力；不承诺下一轮不会再触发。

第一版保留的退让候选只存在本轮内存中，并深拷贝其摘要、覆盖游标和验证信息。不修改旧断点 schema，不强转旧 270 段断点。进程中断后继续复用最新已验证断点，不把未提交的内存候选冒充已提交快照。

特别限制：候选来自较早覆盖边界时，构造最终请求必须保留后续尚未覆盖的完整原文，覆盖标记与 Journal 来源必须匹配；不能把早期摘要与较晚覆盖游标拼在一起。

## 5. 目标未达到时的约束

工具定义、系统指令、受保护的新用户请求和正在执行的工具链本身可能占据大部分体积。摘要文本变短不保证这些必要部分能缩小。

- 不截断、丢弃或拆开工具调用/结果来制造余量。
- 不把“本轮没有更多安全边界”夸大为数学上永远无法达到目标。除非已计算出可信的必要协议体下界，否则只记 not_met，不能断言 unreachable。
- 不为了目标再增加摘要请求上限、120 秒单次期限、整体时间预算或恢复次数。
- 不在失败时自动采用早期候选来隐藏错误：取消、存储/检查点错误、未知错误继续按原规则传播；结构/传输失败也不能因存在一个退让候选而新增放行分支。
- byte-only 的已知摘要失败仍由原 P0 白名单决定是否发送原请求；token/both 不能因此被降级成纯字节失败。取消后不发模型请求、不提交候选。

这可能使部分边界场景仍频繁越线。第一版不加入隐藏的跨轮冷却或临时提高 B；若后续数据证明有必要，另做带失效条件的设计，不能混入本次余量机制。

## 6. 接入点与兼容性

建议增加内部 BudgetAssessment / CompactionGoal 数据类型，把触发原因、beforeBytes、B、T 与既有 token 条件传入评估器。

- AgentContextSession：解析本轮目标，不持久化派生值到 Provider；保持当前模型/API 的预算重新计算。
- AgentContextCompactor：对完整候选统一测量最终协议体；明确控制提前结束与正常终态的退让选择。
- AgentHierarchicalCompaction：在本地完整收纳事实、模型合并后的边界和正常历史耗尽时使用一致评估；保存已验证进度仍先于候选暴露。
- 旧文本摘要路径和新分层路径都必须覆盖，不能只改新树路径。
- AgentRequestBytePolicy：不因本设计改变其默认值选择；DeepSeek 显式 2 MiB 始终是独立变量。
- AgentCompactionRequestBudget：摘要请求自身的容量门槛保持原样，T 仅指最终聊天请求目标，不把目标误套到单段摘要请求上。
- 最终历史仍由原有 snapshot 原子发布；原 Journal 与工具结果保存规则不变。

用户在两轮之间更换模型、API 或预算时，重新生成本轮目标；不能把前一 Provider 的 B/T 或内存候选直接带入新请求。已验证历史摘要是否可复用仍由既有来源与预算检查决定。

## 7. 可观测性与显示

只增加安全数值与固定枚举，候选字段：before_bytes、after_bytes、byte_budget、byte_target_bytes、headroom_bytes、byte_target_status、trigger、decision_id。

byte_target_status 至少区分 met、not_met、not_applicable。失败、取消继续保留原始错误分类；不把目标未达标显示成网络超时或摘要结构无效。

普通界面可简短提示“已压缩，近期必要内容较大，可用余量有限”；只有实际达到目标时才声称已恢复对应空间。不向用户展示未经证实的服务商剩余容量或“保证不会再次压缩”。

应同时记录：达到目标所用摘要请求数/等待时间、退让次数、之后多少轮再次发生字节压力。不能只用越线比例衡量收益；压缩更彻底可能增加这一次等待和信息损失，需要一起验收。

## 8. 离线验收清单（待实现后执行）

| 场景 | 必须满足 |
| --- | --- |
| 2 MiB 预算，当前 1.59 MiB | 不因 1.5 MiB 压后目标而提前触发 |
| B 与 T 精确边界、B+1、极小预算、Int.MAX_VALUE | 严格触发与 Long 运算正确，不溢出 |
| 2 MiB 越线，候选依次为 1.98/1.70/1.49 MiB | 前两者不误判达标，最后在完整工具边界提前结束 |
| 正常耗尽历史，最佳有效候选 1.70 MiB | 可有限退让，明确未达目标，覆盖游标与剩余原文准确 |
| 受保护部分太大 | 不截断、不拆工具、不重新执行；不把软目标未达变成硬容量错误 |
| 早期候选后取消/未知错误/存储失败 | 不提交候选，不扩大 P0 放行 |
| token-only、both、Provider 超窗恢复 | 原有 token/恢复门槛保留，不降级为纯字节兜底 |
| byte=0、手动压缩、任务结束压缩 | 新目标不作用于不适用路径 |
| 旧文本断点、新分层树、本地事实收纳 | 早停与终态判定一致，旧格式兼容 |
| JSON/工具定义/图片/协议状态导致体积变化 | 以实际最终协议体复测，不以摘要字数推断 |
| 早期候选与后续原文拼接 | 不多覆盖、不漏覆盖、不改 Journal 来源顺序 |
| 换模型/API/显式预算 | 新一轮重新解析目标，不复用旧 Provider 的目标 |

这些是待实现的验收条件，不是已经通过的新增测试。本轮只有 2 MiB 观察器的本地合成元数据测试通过，没有余量算法产品代码变更。

## 9. 与当前 2 MiB 正常使用验收的分工

用户已选择临时 DeepSeek 显式 2 MiB，由用户正常使用验收，不自动生成测试消息。记录越线、压缩前后体积、终态决策与 HTTP 状态；50 个请求或 24 小时后条件恢复原 null，不覆盖用户期间另设的值。

本轮可验证候选阈值下的实际行为，却不能验证尚未实现的 25% 余量目标。若实际请求没有越过 2 MiB，也只能确认该范围内的使用，不补发大请求凑触发。需要主动模型请求或超过既有观测范围的专门测试时另行确认。

依据：[正式采样报告](DEEPSEEK_REQUEST_BUDGET_SHADOW_REPORT_2026-10-20.md)、[现有 P1 策略](REQUEST_BYTE_POLICY_P1.md)。

## 10. 第一版实现切分（2026-10-21，候选分支）

本版只实现分层摘要路径的候选策略与遥测；未构建 APK、未安装、未做真机验收，不能视为已生效。

已实现：

- `AgentByteCompactionGoal`：仅当本轮 reason 为 `bytes` 或 `both` 且 B>0 时定义 T=floor(B×3/4)，使用 Long 运算；触发条件仍是严格 `requestBytes > B`，T 不是触发线。
- `AgentCandidateVerdict` / `AgentContextCompactor`：分层路径的完整工具边界候选分为三种：≤T 立即采用并停止（TAKE_AND_STOP）；T<bytes≤B 保存本轮最小候选并继续（RETAIN_AND_CONTINUE）；>B 或 token 超限拒绝（REJECT）。正常耗尽历史后，只有最终候选被拒绝时才回退到已保存的 ≤B 候选；摘要异常仍按原错误传播，不用候选掩盖失败。
- `AgentContextSession`：preflight 字节/双压力把目标传入 compact，并随 pending 决策保存；`compact_done` 遥测增加 `byte_target_bytes`、`headroom_bytes`、`byte_target_status`（met/not_met/not_applicable），仍带同一 `decision_id`。
- 未改 token 80% 保护、P0 白名单、取消/检查点/未知错误、手动与终态压缩、Provider 预算派生/显式覆盖；未改断点 schema。

限制与后续：

- T=75% 是固定工程参数，尚未配置化，也尚无真实压缩频率/信息质量数据。
- 旧文本摘要路径没有提前候选回调，仍会跑完整摘要并返回最终候选；本版对文本路径只记录目标结果，不改变其早停行为。文本路径的候选/退让是下一独立切片。
- 目标未达时的界面提示、跨 Provider/模型切换、多工具轮再触发统计、以及 2 MiB 显式覆盖的真机验收仍未实现。

本地回归（候选分支）：`AgentByteCompactionGoalTest` 3、`AgentHierarchicalCompactionTest` 26（含 retained candidate）、`AgentBudgetTelemetryTest` 4、`AgentBudgetTelemetryIntegrationTest` 13、`AgentRequestByteCompactionTest` 26，均 0 失败；尚未跑完整设备验收，也不替代第 8 节清单。
