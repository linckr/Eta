## 2. 许可、决策和恢复语义

- 原模型步骤在准备发送/压缩失败处暂停；先发布原始 transcript 与上下文快照，再发布决策，不从最初用户消息重跑任务。
- 决策绑定 runId/requestId/nonce/revision；多个入口只能接受一个动作，旧按钮和迟到 ACK 不能授权新请求。
- 存活决策最多等待 15 分钟；确认后发送 lease 最多 60 秒。使用包含休眠时间的 elapsedRealtime；工作线程每秒复核等待截止时间。
- 许可只适用于 CHAT、有效 v4 策略、S>L、未超 H、无 token 压力、非签名工具回合且没有模型自定义头/体覆盖的请求。未知窗口显示未知，不声称容量已经验证。
- 请求正文、配置、会话、目标端点、账号身份和当前工具目录绑定。确认后和消费前再次校验；变化即失效，不自动刷新许可。
- 暂停期间普通 resume 不能授权；新的补充指令被拒绝并保留草稿，避免它悄悄改变已确认请求。停止遵循用户停止的队列语义。
- “重试压缩”作用于当前 worker 保存的上下文，不重放已完成 Android 工具。没有已核验断点计数时显示“未验证”和“重试”，不会伪造“继续到第 N 段”。旧树导入没有实现。
- 冷启动/归档不恢复 nonce 或可用许可。存活 run 的 IPC 重附着可以显示当前决定。终态保留失败原因，通过手动压缩入口恢复，不自动再次发送原请求。
- 浮窗/通知只能打开 Eta 恢复面板；仅 app 自身 UID 可以提交恢复动作，助手 Hook 进程不能授权。

## 3. 一次物理模型 HTTP 调用

`AgentOneShotHttp` 是 Chat Completions、Responses、Anthropic Messages 的集中入口；旧的非活动 Codex adapter 明确拒绝一次许可。普通非许可请求保持原来的有限恢复行为。

许可消费发生在创建 Call 前，之后不会因正文未写出而返还。RequestBody 标记为 one-shot，并禁止第二次 writeTo。

|情况|本许可允许第二次模型 HTTP 请求吗|界面/恢复|
|---|---|---|
|连接失败，尚未写正文|否；已消费|显示未完成，重新发送需重新确认|
|307/308 重定向|否|不跟随；保留原历史|
|401|否|不因本次 401 刷新后重传；凭据恢复后需要新的决定|
|408/503 或可恢复网络错误|否|关闭连接恢复和 Agent 安全重试|
|空响应、DSML/工具协议异常|否|本次不执行格式纠正重发|
|流开始后中断|否|保留已有结果/检查点，明确未完成|
|完整响应且校验通过|否；本次已完成|许可不传播给下一轮，下一轮重新检查 L/H/token|

严格 client 统一设置 followRedirects=false、followSslRedirects=false、retryOnConnectionFailure=false、Authenticator.NONE、ProxyAuthenticator.NONE。401 前为了首个模型请求获取有效凭据，和 401 后重传模型正文，是不同动作；本许可禁止后者。

上述“物理一次”指 Eta 发出的模型 HTTP 请求。供应商内部实现不受客户端控制；不能据此保证任意未知反代的上游调用次数。

## 4. 请求绑定资源边界

- 冻结正文上限 **16 MiB**；先计算 UTF-8 字节数，再决定是否分配冻结 byte[]。不合格请求额外保留的冻结正文为 0 字节。
- 二次检查用流式 SHA-256，实际 outgoing body 用带长度约束的流式哈希，不再分配第二份完整正文 byte[]。
- 消费前在哈希完成后再校验截止时间、账号和配置，避免大正文计算期间过期仍然消费。
- 这不是整个 Runtime 堆内存上限：原历史、JSON 和字符串仍占内存。超过 16 MiB 时不提供一次许可，不能把它描述为任意大正文都安全。
- 2 MiB 绑定用例要求本测试主机 10 秒内完成；超 16 MiB 的中文正文验证不保留冻结副本。尚未对低内存真机做堆峰值或严格 UI 延迟验收。

候选基于公开 tag v1.13.12 的固定 commit `9976995e6e227dd2986448b4675e8baaae8ed5df`。不是当前生产 EXE 的源码等价证明，也不含已部署诊断版的全部差异，不能直接覆盖生产程序。

- `X-Eta-One-Shot: v1` 只增加限制，不是 Eta 授权凭据；未知/重复值拒绝。
- 同一入站 context 共享原子消费状态，禁止重用；关闭瞬态重试、账号池 failover、重定向和正文 GetBody 重放。
- 标准 Transport 使用独立 HTTP/1、不复用连接；生产自定义 Transport 仍需专门审查，fake Transport 仅用于离线计数测试。
- 401/408/429/503/307 的双账号 upstreamChat 测试确认只进入一次上游，不删除原账号。
- 候选 `/health` 可声明协议，但当前 Eta **尚未接入受信任的网关能力激活流程**。人工添加 header 不能解除客户端的 WorkBuddy 阻断。
