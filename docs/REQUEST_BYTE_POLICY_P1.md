# P1：按有效输入预算选择本地上传软预算

日期：2026-10-19。候选版本：3.3.1-local / 2026101901。

## 策略

| Provider 配置 | 当前请求的上传软预算 |
| --- | --- |
| 显式 0 | 关闭字节触发，token 保护保留 |
| 显式正数 | 原值优先，所有模型共用该覆盖值 |
| 留空，有效输入预算 ≥ 256,000 tokens | 1 MiB（1,048,576 B） |
| 留空，有效输入预算更小或未知 | 512 KiB（524,288 B） |

256,000 是十进制 token 数；字节阈值采用二进制单位。未知窗口保持保守旧值，负数旧运行配置按缺省解析。有效输入预算沿用现有模型容量逻辑：显式 input limit 与可用窗口取较小值，已明确为 total 的窗口扣除请求输出上限。摘要请求另保留原有计划输出预留，再使用其有效输入预算选择默认值。

这是本地策略启发式，不代表 token 与 HTTP 请求体存在固定换算关系，也不代表 API 硬上限或容量已获服务商验证。按当前模型重新解析，不把派生值写回 Provider；切换模型/API 后不会沿用上一模型的派生值。显式 48 MiB 覆盖仍为 48 MiB，若要验证新默认需清空覆盖。

共用 AgentRequestBytePolicy 的入口为聊天请求前检查、压缩候选的最终请求验收、摘要请求输入预算和 DSML 格式恢复提示的临时请求检查。避免聊天允许 1 MiB、恢复路径仍按 512 KiB 的不一致。摘要时间预算、次数、重试白名单、取消、检查点、工具边界和最终提交路径没有改动。

## 冻结基准与验收范围

冻结样本的原请求为 540,885 B，估算 183,591 tokens，有效输入预算 1,000,000 tokens。旧 512 KiB 策略触发过一次结构校验失败的摘要，随后 P0 回退原请求完成；48 MiB 对照未触发摘要且聊天完成。该成对实验不构成 100–200 轮分布样本，也不能证明服务商接受任意 48 MiB 请求。

已核对冻结清单中数据库与四个证据文件的 SHA-256 全部匹配。未改冻结目录，不将数据库、日志、会话正文或设备标识提交到仓库。新增回归使用冻结指标以及本地合成的等体积请求，不向服务商回放真实会话。

本地验收覆盖：

- 540,885 B / 1M 输入不调用摘要且原请求保留；同尺寸合成请求在本地 Provider fixture 完成一次聊天，不执行工具。
- 1 MiB 前一字节、精确边界均不触发，超过一字节触发。
- 128k/未知窗口、256,000 临界点、输出预留、input cap、显式 0/正数和负数旧配置。
- 切换模型重新解析；token 压力仍触发；P0 白名单回退、取消、硬失败、已完成工具和 checkpoint 保护沿用回归。
- 摘要预算和临时 DSML 恢复请求使用相同默认策略。

## 分布采样工具校正

scripts/request_budget_distribution.py 只计 phase=pre 的 chat 请求；按 decision_id/trace_id 去重。无 ID 记录不猜测去重，单独报告。runtime reason=token/both 优先纳入已观察 token 压力，避免估算偏低时误计为纯字节压力。

上传失败只计明确 write_completed=false；HTTP 非 2xx 独立统计，不能把上传完成后的 400/429 当作上传链路故障。缺失写入状态单列 unknown。增加 shadow_capacity_default_triggers，与现有 shadow_512k_triggers 离线比较；未知 token 压力不冒充已确认的纯字节触发。shadow 指标不执行压缩，且不模拟运行时的所有条件（例如关闭自动压缩、signed tool round 延后），不是实际调用次数的保证。

建议用显式 48 MiB 临时覆盖采集正常使用的 100–200 个 chat 请求前检查（含工具轮次，不等于 100–200 条用户消息），之后恢复原配置。采样和 P1 默认验收分开进行，避免 48 MiB 覆盖掩盖默认策略。本次未调整手机配置或新增订阅请求。
