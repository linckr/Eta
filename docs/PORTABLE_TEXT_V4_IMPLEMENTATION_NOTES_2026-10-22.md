# v4 便携文本摘要实现边界

## 已接线的受控实现

- 仅 `ModelConfig.compactionPolicyVersion >= 4` 进入新引擎；旧配置继续原文本/结构化树策略。
- 手动压缩与普通聊天共用 Runtime Executor → ModelClient/Loop → Session → Compactor → Summarizer；不另开模型或执行历史工具。
- 新引擎保留现有安全 JSON 切片、来源游标和整批工具边界。字段中的进度可以保存，只有完整边界可形成提前提交候选。最终完整请求预算仍由 Compactor/Session 检查。
- Provider 必须正常 END_TURN、正文非空、没有真实工具调用或泄漏的 DSML 调用。20,300 字符正文和17条自然语言事实不再触发旧12,000字符/事实数组校验。
- 流式正文及只提供最终正文的 Provider 均检查256 KiB UTF-8捕获护栏；超过时失败，不截断。8000字符仅是提示目标。
- `accepts` 检查目标余量、允许提前结束；`candidateFits` 检查完整候选合法容量。正常结束且容量合法的候选不因目标偏差重复精简。最终容量不足时至多一次精简，与网络/上游超窗恢复共享一次额度。纯本地切片输入预检缩小不发送请求。
- 已验证进度存于原 checkpoint 私有目录的 `portable-v4` 子目录，record version=3，保存 engine/algorithm/prompt/canonical标识、完整响应状态和来源指纹。原v1文本文件与树文件不读写、不删除、不强制转换；旧270段继续使用原引擎。
- 有稳定会话ID时，定位key按会话scope/角色模式/算法/提示/canonical版本计算；manifest另存客户端已消费前缀证明（规范digest、已消费消息数、源总数、游标）。新消息append不改变定位，也不令已验证前缀失效；同源v4文本进度可跨模型复用，新模型输入预算重新计算。编辑/重排已消费来源、此前受保护的用户消息重新插入前缀，使证明失效并从匹配来源重建，绝不凭稳定key盲目复用。
- 部分字段证明覆盖已消费消息/字段值和当前字段前缀，并绑定已被片段元数据暴露的字段总长、批次起止及role/tool IDs/names。只允许等长未消费字符串suffix改变；字段长度、已消费字或批次结构变化拒绝续用。半字段游标仍不能提交为完整工具边界。
- 完整消息的规范前缀根在单次运行中增量缓存，保存后续片段不再重复扫描全部已消费消息。重新进入任务时仍须复核一次已消费前缀；尚无5000+消息专项性能证明。
- 无稳定会话scope时保留原精确全history fallback，追加历史会新建定位，不声称支持增量恢复。旧无scope format3文件无法证明会话归属，保留原读取入口和文件，不能自动导入到任意新scope，避免相同文本历史的两个会话共享成果。
- 保存仍使用既有私有文件原子改名；候选只有通过原有 Session snapshot 发布后才替换活动历史，失败/取消保留原历史与最近保存的验证进度。

## 本轮没有声称实现的目标接口

`TEXT_COMPACTION_ENGINE_INTERFACE_2026-10-22.md`中的全量 JournalViewRef、Room节点引用、不可变artifact仓库、跨文件/DB引用提交协议、lease垃圾回收、generation CAS以及旧树到新文本的只读桥接，仍是后续架构工作。本轮是已接到现有提交器的隔离滚动文本实现，不是上述完整新架构。

这些接口不是修复 L_observed/L_send_policy 语义和格式依赖的先决条件。复用已有安全来源/边界与会话提交器，避免在本次候选中强行重写或迁移270段既有成果；真实跨进程编辑竞争、只读旧树桥接和新Room架构不得据本轮单测宣称验收。

来源证明逐消息规范化哈希并缓存本轮完整消息前缀根，但尚无5000+消息的CPU/内存专项性能验收；单条巨大消息仍会分配其规范化表示。后续来源索引性能优化需独立测量，不能以此次没有整份拼接推断已达性能预算。
