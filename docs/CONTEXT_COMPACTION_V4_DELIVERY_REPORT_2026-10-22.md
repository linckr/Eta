# Eta 3.3.1：压缩策略 v4 开发与交付报告

日期：2026-10-22，Asia/Shanghai。基线：`366ce7dea209e80250a5ff0af75b3d58fcb7470e`。本报告区分设计、已接线源码、本地验证与真实验收；不是手机安装或模型质量通过证明。

## 1. 这次修正了什么

精确成功观测不是自动发送上限。v3 中将一次成功的 `1,782,914 B` 直接用作 L 的条款已作废，否则下一条普通消息就可能再次触发昂贵摘要。

v4 使用启用时冻结的基准和增长余量：

```text
anchor = 用户确认的同路由成功观测；没有则使用明确标注的 bootstrap
G = clamp(ceil(anchor / 4), 256 KiB, 512 KiB)
L_send_policy = min(anchor + G, 已知 H)  // H 未知时不假设服务端容量
```

样本结果：`anchor=1,782,914 B`、`G=445,729 B`、`L=2,228,643 B`。这是有限、可见的本地策略空间；增长段未经真实上传验收，不是 API 支持容量声明。成功观测不自动滚动抬高 L/G。当前观测值由用户确认后录入，未接自动成功包络采集器。

新策略默认关闭，已有配置保留原行为。不存在未经用户选择就把所有大窗口模型切成 2 MiB 的变更。

## 2. 唯一 B/L/H 语义

| 配置 | v4 含义 |
|---|---|
| 原 `request_byte_budget=NULL` | 不额外派生软字节压缩线；token/L/H 继续有效 |
| 原字段为 0 | 关闭软字节触发；不关闭 token/L/H |
| 原字段为正数 B | `S>B` 时先尝试软压缩，等号不触发；即使 `B<S<=L` 也不能忽略 B |
| L | 自动发送边界；摘要/重试也必须遵守，失败不能绕过 |
| H | 用户有证据的接口硬限制，未知留空；不得当成本地经验值 |
| L_observed | 观测证据，不参与自动提高已冻结边界 |

当 token/B/H 均无压力且 `S<=L`，`S=L_observed+1` 不启动摘要。L 越线才触发护栏整理；如果已知相同来源存在持久性摘要失败，则直接提示手动处理，不再自动重跑同一失败摘要，也不发送越界原请求。

字节压缩目标为 `min(floor(0.75L), L-G)`；显式 B 更小时还须争取相应软预算余量。目标与允许发送边界分开：有限余量候选不伪称达标。固定其他压力条件且压后达到目标，随后 10 轮新增总字节数不超过 G 时，不应再次命中 L 护栏。任意大工具输出、独立 B 和 token 压力不在这条保证内。

## 3. 已接入的产品路径

### 3.1 设置、IPC、数据库

- 提供商设置新增实验性 v4 开关、已确认观测值、已知 H、冻结 L/G 预览。
- 当前范围是一个提供商路由，覆盖该提供商无独立请求覆盖的模型；不是逐模型验收结论。
- 地址、协议、凭据或请求覆盖变化会使策略失效，需重新明确开启。模型独立请求头/请求体被排除，页面列出具体模型并说明其沿用旧策略、不受此 L/H 保护。
- 统一配置与 IPC 五字段：策略版本、观测值、冻结发送边界、硬限制、冻结增长余量。旧请求未携带版本时仍为旧策略。
- Room v24→25 显式迁移：保留 B、会话和检查点；新增策略 JSON 与无正文的失败记录表。新包移除缺少迁移时的破坏性清库回退。

### 3.2 纯文本摘要候选

- 显式 v4 路径选择滚动文本引擎，不要求模型生成版本、来源 ID 或事实数组。来源、游标、版本由客户端绑定。
- 20,300 字符不再仅因超过旧 12,000 字符阈值失败。必须正常完成、非空、无真实工具调用/协议泄漏，并通过完整最终请求预算检查。
- 256 KiB UTF-8 为正文捕获保护，不能当成服务端输出保证或进程峰值内存证明；超出不会机械截断为“完整摘要”。
- 只有完整响应才推进来源游标。完整工具交换/消息边界才可形成可提交候选；片段进度不能冒充完整工具结果。
- 一次精简与传输恢复共享受限恢复额度。摘要请求本地超边界可缩片；最小片段仍不合格时有界失败，保留历史和已验证成果。
- 新断点使用独立 `portable-v4` 空间、记录版本 3。旧文本/树/270 段文件不强制转换或删除；关闭 v4 后仍由旧读取器续压。新路径不会自动继承旧树进度，首次可能重新整理，切换前应知悉。

### 3.3 失败恢复与发送前守卫

- 同一会话/来源和策略下的格式、无收益、捕获/输出预算等确定性失败可持久抑制自动软重试；临时网络故障只在当前运行内抑制。
- 失败表只保存 HMAC 来源标识、版本、错误码、时间与计数，不保存正文。HMAC 密钥仅应用私有存储，按消息和编码块处理，不拼接整份前缀。
- 来源变化、路由/预算/摘要模型或算法版本变化使相应记录失效；新增普通消息本身不会解除相同旧来源的确定性失败。
- 现有手动“压缩上下文”走 force 单次尝试，绕过自动抑制；并非永久封死恢复。
- P0 回退只允许已知摘要失败、byte-only 且原请求仍在 L/H 内。取消、存储错误、未知错误不软化；工具不重放。
- 每次实际模型尝试（含 DSML 协议修复增量）重新测量并检查 L/H。摘要请求也检查；没有单次越界许可 UI，因此超过边界失败关闭。
- 快照成功发布后才切换活动上下文和清理对应断点；快照失败保留原历史/失败记录。成功提交后的失败记录清理错误只作无正文诊断，不撤回已提交成果。

### 3.4 usage 与时间预算

- 新诊断区分 input usage 的 available/partial/missing，不能把任意 usage 事件或尚未完成读取阶段的 0 当成有效输入 usage。
- 缺少可用输入 usage 时继续使用本地估算，不伪造 provider token 数，也不据此学习容量上限。本次没有新增已获真实标定的 token 校准器。
- 保留现有总体/单次预算，不把未通过真实成功率验收的 45 秒候选直接作为默认。不能承诺本次本地回归证明真实摘要必在 45 秒完成。

## 4. 实现架构与明确未接入项

本次使用既有 Session 快照发布、来源校验、Journal 留存及独立文件断点，不引入全量 Journal 重建。最初接口草案的 Room 不可变 artifact/node、独立 generation CAS 协调器、旧树只读导入桥接尚未接入，不把草案类型当作已编译能力。既有运行中的来源并发协调沿用原快照机制，不宣称新 CAS 保证。

一次越界许可、自动观测采集、逐模型路由策略，以及跨供应商的自动容量探测也未接入；未实现的授权入口不采用自动放行替代。

## 6. 需要用户注意与后续真实验收

1. **候选包尚未安装，新策略尚未启用。** 任何安装仍需单独授权，并先私有备份数据库。升级 DB25 后不要直接降级旧 APK；旧 APK 自身可能清库，应使用已验证备份恢复流程。
2. **增长段不是已验证容量。** 对目标 DeepSeek 路由，可用上述已观测 anchor 预览 L/G；是否启用及是否发送增长段请求需要明确验收，不能外推 WorkBuddy/intern-ai 或不同网络。
3. **旧断点不会自动转换。** 有昂贵的未完成旧树时，先完成原路径或明确接受新路径重新整理，文件仍保留。
4. **摘要语义质量仍需核对。** 结构正确不等于事实完整；必须从原 Journal 抽查关键工具结果、失败/成功状态、路径、约束与未决事项。
5. **真实性能/成本尚未通过。** 自动成功完成率、暂停率、手动续压率、模型耗时/费用和缓存命中只能在授权后的代表性任务测量，本次不编造数字。
6. **固定验收建议：** 同一冻结历史在 L_observed+1 不发摘要；一次成功压缩后做总增量≤G 的 10 轮；明确测试 token 压力与 B 独立触发；同源摘要失败后下一轮不重跑、超 L 立即阻止；手动重试可用；切换 API 后重新检查当前窗口/路由策略；取消/存储失败不丢原历史。质量关键事实建议逐项 100% 保留，非关键事实另评分，成本/缓存与旧包同输入对照。

正式默认发布仍须满足下列门槛，当前均未获真实模型验收：

| 指标 | 发布门槛 |

| 自动压缩完成率 | ≥95%（非故障注入的受控代表性负载） |
| 预算暂停率、手动介入任务比例 | 各≤5%，不能以用户续压代替自动成功 |
| 压后原请求继续完成率 | ≥95%，传输失败单列 |
