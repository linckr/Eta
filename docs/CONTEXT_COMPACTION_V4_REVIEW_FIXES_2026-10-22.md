## 2. 三项缺陷与修复契约

### 2.1 token 不能只满足小于100%窗口

问题成立：2201将95%I的候选作为合法最终结果，可导致下一轮立即触发85%自动压缩。

统一规则：v4提交接受上限为 `floor(80%I)`；85%仍是自动触发线，60%仍是提前达标目标。early候选、retained候选、正常最终返回及单次精简后回填使用同一判断。95%不能提交；80%到60%间是余量有限候选，不能假称满足10轮目标。只有达到60%且10轮累计增量≤20%I、其他条件不变时，保证不再命中85%触发线。

### 2.2 bootstrap 必须独立于 B

问题成立：2201在观测留空时从旧B取anchor，48MiB采样配置会间接放大L。

修复：观测留空时固定独立anchor=512KiB，G=256KiB、L=768KiB，再受已知H裁界。null/0/2MiB/48MiB的B均不改变这些值；B原值仍保留，正B>L时保留警告。显式、已确认观测值优先；已冻结L/G不随B变动而滚动提高。

旧2201已经保存的bootstrap也不能继续继承大L：新增bootstrap规则版本标记，旧bootstrap失效，页面明确显示沿用旧策略、当前不受此L/H保护，需用户重新明确启用后生成独立固定边界。真实观测值的冻结策略不因此被静默缩小。手机当前全部v4关闭，本轮未修改其设置。

### 2.3 追加历史应复用来源未变的已验证进度

问题成立：2201对整个history计算定位key，新增消息会换key，即使旧来源完全相同也无法恢复原进度。

修复方向：稳定会话scope用于定位，新断点绑定实际已消费来源前缀与游标，读取时独立复核。完整边界按已消费消息数重新定位；追加未消费消息可续压，编辑/重排已消费来源不得复用。半字段断点仍不能直接提交为完整工具结果，必须验证已消费文字、字段路径/类型及相关结构元数据。无稳定scope时明确回退全历史绑定，不能跨会话猜测复用。旧格式断点不强行转换或删除。

实现已接线：完整消息前缀根在同一次运行内逐条缓存，避免每段重新哈希整个旧前缀。部分字段绑定已消费前缀、字段总长度、已消费字段和工具批次元数据，只允许等长的未消费suffix变化。证明和摘要在同一个JSON中原子落盘。2201无scope的旧format3文件保持原文件，仅无scope的精确历史入口可恢复，不自动导入另一会话。旧文本/树/270段文件仍不强制转换。

这里的增量复用以“传入摘要器的已消费来源前缀不变”为条件。若新请求导致原受保护用户消息重新插入旧来源前缀、或工具批次结构发生变化，必须安全失效，不能仅凭用户说“追加”就放松来源校验。
